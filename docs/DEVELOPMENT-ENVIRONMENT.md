# 开发环境与目录

更新：2026-11-17。本文件记录当前开发分工；实际主机、凭据和资料恢复状态由维护者的项目私有记录提供。历史交接与发布记录保留原始事实，不作为重新执行的授权。

## 工作电脑

- Mac mini 长期源码工作区使用 `~/Codex/projects/terry-toolbox`，保存源码、Git 历史、文档、必要资源与受保护连接凭据。MacBook 旧工作区在恢复验收前保留；过渡任务使用所在机器真实存在的入口。
- Mac 的轻量源码只用于查看与同步已审查合入的 `main`；源码及项目规范在开发机独立任务目录编辑，持续 WIP 留开发机，不为新任务在 Mac 创建或编辑源码工作树。大型恢复包、数据库、测试机镜像、历史产物和依赖缓存不搬入 Mac；恢复时按仓库入口在开发机取用或重建。
- Codex 内部状态沿用 `~/.codex`，总规范为 `~/.codex/AGENTS.md`；无项目聊天工作文件使用 `~/Codex/chats/<日期>/<聊天目录>`。聊天目录不能替代会话状态，应用管理的工作树不手动移动。
- 本项目连接入口使用 `.private/ssh/config`，必要密钥和固定 `known_hosts` 保存在同一受保护目录。目录权限为 `0700`，秘密文件为 `0600`，`.private/` 排除 Git 与所有公开源码包和构建上下文。
- 实际开发机别名、工作目录、旧端来源、私有证据位置及资料恢复缺口写入 `.private/DEVELOPMENT-LOCAL.md`。连接前读取此记录与当前配置，核验目标身份和已固定主机指纹；不从历史 IP 猜测、不自动接受未知 key、不引用其他项目的私有入口。
- 公开规范只写通用路径和分工，不写个人绝对 home 路径、私有地址、主机指纹或凭据。`.gitignore` 不能保护已跟踪秘密，提交与打包前仍须检查内容。

## 执行与发行

- 开发机正式 `main` 位于 `/srv/projects/terry-toolbox/main`，新实施／文档／检查任务位于 `/srv/projects/terry-toolbox/tasks/<任务>`，从已核对的最新 GitHub `main` 建立 `codex/<任务>`。原 `/srv/projects/terry-toolbox/repo` 保留历史候选及在途工作，不切换或覆盖。依赖、测试、预览、容器、数据库、编译与发布工具只在开发机本项目隔离目录使用；工具、缓存、私有记录及候选产物各自保存。
- 每次先检查 Mac、开发机正式 `main` 与任务目录的 Git／HEAD／暂存／WIP、所有关联 worktree、GitHub remote／PR 和活动归属；保护未推送提交及原任务分支。日常修改只在独立任务目录执行，正式副本只按下节已验收 `main` 正常快进。开始重任务前核对占用，不覆盖其他项目源码或修改共用宿主设置。
- 测试脚本仍有受保护 root fixture、工具版本与新建输出目录等约束，按 README、HANDOFF 和脚本当前门禁执行；不在迁移中放宽门禁，也不在 Mac 回退运行。缺少适用环境时记录缺口并准备隔离环境。
- 真实服务安装/卸载、内核、网络、防火墙、磁盘、重装和重启验收使用用户授权的专用临时测试机；共用开发机、用户 Mac、生产与其他项目机器不能充当可擦除目标。
- 发行继续现有 Cloudflare Workers 流程，按本次发布授权核对构建、备份、上传和外部回读。源码或文档同步不触发发布、域名变更或历史 adapter 重跑，GitHub 继续保存可公开的源码和审查记录。

## 日常开发与每轮收尾

本节是本项目 Git、正式 `main` 同步和引用／资源清理的唯一现行流程，适用于单独开发聊天及已明确分工的协作任务。公开源码和文档只能包含可公开资料，私有目录入口仍按上节读取。

默认当前主负责人同时是本轮实施与收尾负责人，承担开发机实施、审查与精确验证、PR 合入 GitHub `main`、开发机及 Mac 正式 `main` 安全同步、已合引用与一次性资源清理、回执及未完成项责任。只有用户或当前任务明确指定另一负责人，且对方实际收到并接受具体交接后，才能转移约定的 Mac 同步或清理责任；仅写“交给调度／另一个聊天”不算交接完成。存在调度时按已接受的明确分工执行；单独开发聊天直接由当前主负责人完成全流程，无需额外调度器、聊天或周期任务。

1. 从实时 GitHub `main` 的准确基准建立开发机独立任务分支，阅读相关实现并分批保存明确文件。审阅差异、暂存与敏感资料，确认实际 GitHub 写入权限后普通推送任务分支；未验收 WIP 不进正式 `main`。
2. 记录精确 source／head／base 与相关检查；文档修改检查内容、链接、差异、敏感字段及实际 Git／目录，不运行无关应用构建。完成审查及所需检查后按本仓库 PR 流程正常合入 `main`，不直接推未经审查的 `main`，不 rebase／amend／reset／强推，不改已发布标签。沿用本项目现有 CI 和 Cloudflare Workers 发行方式，不为了规范维护启停工作流、触发发行或改变域名。
3. 快进前核对正式目录与 `main` 分支、tracked／staged／untracked 源码干净、无活动源码写入者，并确认私有资料仍受保护且被忽略。读取 PR 的实际 source／head／base／merge 与 GitHub 当前 `main` 完整 SHA，核对受验源码、合并树差异和祖先关系。两端分别 `git fetch origin main`，比较 fetched SHA 与已接受的 GitHub expected SHA，再 `git merge --ff-only <已核对的完整SHA>`；不得 reset、强推、覆盖文件或切换持续 WIP 制造一致。若主线在同步期间前进，先核对新增 PR／来源及已验增量，再快进并重新读取三端 SHA。阻挡时保留原件，记录路径、状态、责任人与具体待完成项。
4. 收尾负责人核对所有关联 worktree、分支／远端引用、PR 状态、expected SHA／祖先关系、当前任务归属、活动进程及恢复依赖，只精确清理本任务已合入且无活动归属或依赖的 refs。远端分支已自动删除时仅清理相应本地引用；当前聊天仍需使用的干净任务目录可保留在已验收的 detached 提交，不能据旧回执关闭人类仍在协作的聊天或 agent。应用管理的工作树使用原生可恢复 archive，主／共享工作区保护拒绝时保留并记录原因，不绕过保护删除目录或聊天。
5. 停止本轮所属且已无活动任务的一次性 service；删除 cache／build／临时依赖前核对来源、Git 跟踪、进程与可重建性，按明确清单处理，不批量删除旧开发目录、全机 prune 或仅按年龄清理。持续 WIP、独有源码、真实运行程序／数据、签名、必要回退资料、许可证要求的对应源码、唯一备份和未解决证据保留。回执记录实际清理与保留原因，不能仅承诺“以后清理”就结束。
6. 完成后再次核对 GitHub `main` 与开发机、Mac 正式 `main`／HEAD 是同一完整 SHA，且两端干净。保存本轮修改路径、精确 source／head／base、PR／merge／main、实际检查命令与结果、两端路径和状态、WIP 保持证据、资源归属、refs／service／cache／build 的实际处理、交接受让人与仍待完成项。完整私有证据留开发机本项目受保护目录，Mac 仅留轻量回执。仅保存任务分支或未验收代码仍留开发机，不写成完整交付；发行、生产部署及真实业务验收仍按各自授权与指南另行记录。

## 迁移与保留

- 恢复前核对源和目标状态，保留当前分支、Git 历史、WIP、必要资源及唯一私有资料。只克隆主线不能代替恢复未推送工作，改路径也不能代替实际搬迁与验收。
- 原始日志、凭据、测试机镜像、数据库、私有发行恢复资料与唯一故障证据继续放在已确认的受保护来源，按需精确恢复；不整体搬入 Mac mini 日常源码目录。可重建依赖和构建缓存不默认迁移。
- GitHub 保存完整已审源码、必要资源、构建与发行脚本、配置模板及文档。开发机测试数据按用户当前要求可丢弃，失联后从仓库重建新的隔离测试环境，不再为测试数据建立 Mac 独立恢复副本。检查旧分支和未推送修改后再判断源码已完整保存；新的主线不能代替尚未保存的工作。
- Cloudflare Workers 已发布内容不向开发机或 Mac 回源。重新发布仍需对应 Cloudflare 账户、令牌和域名权限；本次源码迁移没有验证新机发布认证，也不授权发布或重绑定。恢复源码、重建测试环境与恢复生产身份分别核验。
- 核验源码与资料哈希、权限、聊天正文、附件、项目关联、Git/SSH 与远程工具，再记录独立运行和仍留旧端的缺口。历史正文和证据来源路径不为整理目录盲改。
- 在新机完整性和独立运行验收前保留旧端原件；未解决证据、唯一回退资料、生产凭据及真实运行数据不按缓存删除。生产所需非 Git 数据走受保护备份；可重建测试数据不作为旧机迁移的额外备份要求，公开仓库不保存秘密。
